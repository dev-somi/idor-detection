# 0003. 토큰·시간 측정 방식, 프롬프트 v1 고정, 예제 수정 1건

- 날짜: 2026-10-24
- 상태: 채택

## 맥락
- Ollama는 같은 앞부분(시스템 프롬프트)을 KV 캐시로 재사용한다. 이 때문에 토큰 수와 시간 측정이 왜곡될 수 있다.
- 2개 사례(case_03, case_06)로 스모크 실행을 했다(`runs/smoke_20261024-153035_qwen2.5-7b`). case_06 C/D에서 모델은 반환값을 무시한 `is_owner(...)` 호출을 검사로 보고 no_issue_found로 답했다.
- 누출 방지 테스트가 case_04의 매개변수 이름 `expected_id`를 금지어 "expected"로 잡았다.

## 결정
- **토큰 수**: Ollama 0.40.9가 보고하는 `prompt_eval_count`를 실제 입력 토큰 수로 쓴다. 같은 요청을 두 번 보내 확인한 결과, 캐시가 적중해도 값이 같았다(42 → 42). 이 값에는 시스템 프롬프트와 채팅 템플릿 토큰이 포함된다. 문자 수는 대체 지표로 따로 기록한다.
- **시간**: 추론 시간은 요청 하나의 벽시계 시간이다. 캐시가 적중하면 `prompt_eval_duration`이 줄어들기 때문에, 조건 실행 순서를 사례마다 회전시켜 한 조건에 유리하게 몰리지 않게 한다. 모델 로딩 시간은 실험 전에 모델을 내렸다가 다시 올려 따로 측정한다.
- **문맥 초과**: num_ctx 16384를 쓰고, `prompt_eval_count >= num_ctx - num_predict`이면 overflow로 표시한다. 입력은 자르지 않는다.
- **프롬프트 v1 고정**: 스모크 실행의 오답을 보고 프롬프트를 고치면 이 12개 예제에 맞춘 과적합이 된다. 그래서 v1을 그대로 본 실험에 쓴다. 이후 프롬프트를 바꾸면 v2로 버전을 올리고 새 ADR을 쓴다.
- **case_04**: `_require_match(expected_id, actual_id)`를 `(left_id, right_id)`로 바꿨다. 동작과 정답에는 변화가 없다. 스모크 실행에는 case_04가 없었다.

## 결과
- 본 실험은 qwen2.5:7b, 12사례 × 4조건 × 3회 반복으로 실행한다. temperature 0, seed 고정이므로 반복 간 판정은 같을 것으로 예상하지만, 시간 변동을 보려고 반복한다.
