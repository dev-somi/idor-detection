# 0005. Jev 기반 문맥 선별 조건(E) 도입 보류

- 날짜: 2026-10-24
- 상태: 보류

## 맥락
토큰 사용량을 줄이는 방법으로 Jev(TypeSafe AI, 2026-09 공개)를 검토했다. Jev는 글을 생성하지 않는 결정 모델로, state와 질문을 받아 확률이 붙은 타입 답(choice, score, Noul=불리언 확률)을 돌려준다. 호스팅형 비공개 모델이다.

검토한 설계(조건 E)는 다음과 같다. D(depth2)에 포함된 호출 함수마다 Jev에 "이 함수가 대상 함수의 정책 준수 여부에 영향을 주는가"를 묻고, 확률이 τ=0.5보다 낮은 함수는 뺀다. 최종 판정은 로컬 LLM이 한다. IDOR 판정 자체는 여러 단계 추론이 필요한데, Jev 설명 자료가 이런 판단을 약점으로 들고 있어서 판정은 맡기지 않는 것으로 했다.

외부 자료가 보고한 효과(REFLEX의 강한 모델 호출 66~72% 감소, Medium 사례의 총 토큰 59% 감소)는 유료 API 모델을 여러 단계로 부르는 에이전트 환경의 수치다. 로컬 모델을 한 번 부르는 이 실험 구조에 그대로 적용할 수 없다.

## 결정
Jev를 도입하지 않는다. 코드, 프롬프트(v1), 생성 설정, 조건 A~D는 바꾸지 않는다.

근거는 주 실험 `runs/20261024-153314_qwen2.5-7b/summary.md`의 실측값이다(qwen2.5:7b, 12사례 × 4조건 × 3회, 모든 사례에서 반복 판정이 같았다).

| 조건 | 평균 입력 토큰 | 평균 코드 문자 수(대체 지표) | 평균 추론 시간(s) | 필요 코드 포함 | 재현율 |
|---|---|---|---|---|---|
| B_depth0 | 501.4 | 177.8 | 2.38 | 3/36 | 0.75 |
| D_depth2 | 568.6 | 475.9 | 2.36 | 30/36 | 0.40 |

- 선별로 줄일 수 있는 양에는 상한이 있다. 대상 함수만 남겨도 B 수준이므로 최대 약 67토큰(약 12%)이다. 입력의 대부분은 시스템 프롬프트와 템플릿이라 문맥 선별로 줄지 않는다.
- 함수마다 정책, 대상 함수, 후보 함수 원문을 Jev에 보내야 한다. 그래서 Jev 쪽 입력이 아끼는 양보다 많을 것으로 예상한다. 이것은 측정한 값이 아니라 예상이다.
- 로컬 추론의 비용은 시간뿐이다. B와 D의 평균 추론 시간은 사실상 같다.
- 지금 실험의 문제는 토큰이 아니라 판정 정확도와 필요 코드 포함이다(D 재현율 0.40, 필요 코드 포함 30/36). 선별을 하면 포함되는 코드가 더 줄어들 수 있다.
- 외부 비공개 모델을 쓰면 "로컬 LLM"이라는 연구 전제와 맞지 않는다.

## 결과
- 실험 설정과 결과에는 영향이 없다.
- 향후 과제로 남긴다: 문맥이 수천~수만 토큰인 큰 코드베이스나 유료 API 판정 모델 환경에서는 관련성 선별기(Jev 같은 결정 모델 포함)가 쓸모 있을 수 있다. 그 경우 선별 재현율(필요 함수를 빠뜨리지 않는지)을 함께 측정해야 한다.
